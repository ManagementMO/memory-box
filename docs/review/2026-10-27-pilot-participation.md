# Pilot participation verification

This batch protects contribution effort, adds personal return cues, refines distant lettering and makes existing moderation accessible through a protected browser queue. It preserves the pastel pixel materials, actual shared canvas geometry and the running arrival experiment. All browser activity below is controlled QA, excluded from experiment enrollment, followed by exact fixture cleanup.

## Local and hosted integration evidence

- Full Vitest suite: **61 files, 523 tests**. TypeScript and the optimized Next.js build pass.
- Disposable local PostgreSQL: profile/Auth deletion ordering and the new private report-review migration pass authorization, suspension/revocation, immutable receipts, request replay/collision, concurrent conflicting decisions and Auth-deletion checks. These tests do not target the linked project. Both are included in CI.
- **15 browser cases across desktop/mobile**, run in focused batches: four contribution-recovery/saved-place cases, four world-map/two-builder cases, two actual-presence/cursor cases, two provider-backed cited-Ask cases, two arrival/three-distance/shared-link cases and one bounded starter relevance evaluation. The redundant mobile provider evaluation is deliberately skipped. This count includes the completed reruns after the fixture correction below, rather than counting retries as additional coverage.
- Recovery exercised actual browser localStorage/IndexedDB, reload, explicit resume, text/open-build publication, local image bytes/captions, pending paint and accepted-save cleanup. A second independent hosted session added a real linked response; a saved place retained its unread change across reload and acknowledged it only on an explicit visit.
- Collaboration exercised actual hosted note/photo uploads, source links, painting and realtime receipt between two independent sessions with distinct authorship. Presence existed before pointer movement, remained aligned across zoom and disappeared when its session closed.
- Ask used the configured provider and opened an actual cited original, then returned to the answer without a second model call. The separate starter evaluation reports limited relevance evidence and an image-description coverage gap in [retrieval/performance evidence](../retrieval-performance-evidence.md).
- Desktop 1440px and phone 390px/320px review retained readable compact controls, the mobile sheet/dock separation, touch targets, three zoom presets and no horizontal overflow. New panels use the incumbent butter/lilac/pastel tokens. The Impeccable detector returned no findings on the changed UI before final status-wording refinements. Screenshots remain in ignored local review storage.
- Fresh independent whole-change review found no remaining critical or important findings after recovery ownership/photo races, saved-place journal merge/cleanup and operator session-replacement fixes. A minor storage-denial paint warning was added with an observed failing-then-passing regression.

## Corrections made during verification

An immediate reload after an accepted paint save exposed a test-harness race: tracking the response attempted to read an actor from the browser context after navigation. The fixture now captures its known actor and client operation ID before asynchronous reads, and reconciles the exact committed paint receipt through its cleanup service. The single affected operation was recovered using its client ID, revision, coordinates and fixture author. Only its two originally empty cells at that revision and its exact public event were removed; remaining owned pixels/events were verified zero. Desktop/mobile paint reload tests passed afterward. This was a fixture cleanup failure, not a failed application save.

Recovery wording also avoids promising that an interrupted request never posted. Ordinary resume retains stable IDs, making an uncertain retry idempotent. A record owned by another tab, or a browser without ownership locks, requires an explicit separate-copy choice before issuing new save IDs. Storage failures keep current-tab work usable and disclose reload risk.

## Hosted database and release boundary

Only **20261027164840_operator_report_reviews.sql** appeared in the reviewed linked-project dry run; it was applied without seeds, role files or Vault updates. Read-only hosted checks confirmed RLS is enabled, `anon`/`authenticated` cannot select review receipts or execute the RPC, and `service_role` can append/execute but cannot rewrite receipts. The RPC is security-invoker. No real report was moderated to perform these checks.

The existing security advisors reported the intended anonymous realtime receive policies and disabled leaked-password protection; they reported no error-level finding. Anonymous collaboration policies are part of the guest product. Password-based account linking/recovery is not introduced by this batch.

Production release must still be verified through the PR/check runs and exact Vercel commit, followed by canonical health, operator authorization, browser recovery and ETag checks. Local tests or the applied additive migration alone are not a deployment claim.

## Open evidence and infrastructure work

- No participants were recruited or contacted and no invitations were published on behalf of real people. The [pilot playbook](../pilot-playbook.md) supplies unsent invitations and separate uncoached versus assisted observation protocols. Genuine contribution/adoption/return behavior remains unproven.
- Recovery and saved places are local to the browser. Clearing storage or changing devices still loses guest editing access; optional secure account linking remains future work.
- ETags avoid retransmitting unchanged snapshots but still read/assemble public metadata. Changed snapshots remain complete. The bounded two-concurrent-reader probe is not a 30-person load test, p95 guarantee, spatial paging or realtime capacity measurement.
- Four positive starter queries and one unanswerable case do not establish community-wide search quality. The goose illustration case has no derived description and is explicitly skipped. Community questions, visual relevance and multilingual evaluation remain open.
- Both arrivals receive the same participation changes. Flag allocation, metric definitions, exposure exclusions and matured return windows are unchanged; the common release is documented in the experiment operations notes for later interpretation.
