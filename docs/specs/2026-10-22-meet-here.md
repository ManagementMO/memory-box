# Meet here — review proposal

The previous toybox release is production commit `ff4cf93`. The user requested a deeper product-research iteration as a PR to review before finalization. This work lives on `codex/meet-here`, targets `codex/memory-box-mvp`, and must remain unmerged. The production branch and domain must retain the previous release.

## Product decision

The existing invitation copied the homepage and lost the creation that motivated the invitation. This proposal makes the unit of invitation a specific place or authored original. It extends the approved white/pastel pixel identity and uses the existing real collaboration, authorship and contribution flows. See [research and staged next steps](../research/2026-10-22-product-next-steps.md) for primary sources, evidence limits, and the proposed Waterloo pilot.

The hypothesis is that an exact place and an understandable first action make it easier for friends to create together. Automated checks can establish correct navigation and functioning contributions. They cannot establish adoption or retention.

## Experience

- **Meet here** on the canvas and **Invite someone here** in People open a small ticket with a current-content miniature, coordinates, Copy link, native Share when available, and a selectable link.
- **Share original** opens a link to the current original. Back to original preserves the existing search/source-return state.
- A place recipient arrives at the same world center and scale across screen sizes. A dismissible prompt offers Paint here, Note and Photo. No tool is activated or content published by opening the link.
- An original recipient sees the current attributed original and existing Build on this flow. Removed originals show an unavailable notice at the fallback spot; cached words or images are never embedded in the link.
- A copied link can be bookmarked to return. It does not create a room, confer ownership, promise another person is online, or freeze the canvas.

## Data and navigation contract

The client fragment format is `#at=x,y,z` with optional `&memory=uuid`. Coordinates are world center, not screen translation. `z` is the existing camera scale. Serialization retains two coordinate decimals and four zoom decimals, strips old query/fragment/credentials, and includes only the allowlisted public fields. Original IDs resolve against the current eligible world snapshot.

The parser rejects duplicate and unknown fields, malformed values, nonfinite numbers, invalid UUIDs, hashes over256characters, and values outside existing pilot/zoom bounds. An out-of-world camera cannot be silently changed into another shared spot. Existing originals can extend beyond the writable plane, so an original link deliberately clamps its fallback anchor inside the plane; the original itself still opens through the ordinary story camera.

The link applies once on entry or on a new hash change, after the world loads. Realtime refreshes do not reapply it. Active composition, pending placement, paint tools, brush previews and writes defer incoming navigation. Closing the tool applies it when no preview remains; the existing draft is retained. A malformed/empty hash clears the old arrival cue without destroying the world or a draft.

The shared-place camera command wins over the initial campus camera. Resize preserves the world center. A no-size-change ResizeObserver notification does not interrupt navigation animation.

The miniature is a live local8:5crop around the link center. It uses the current pixels, authored notes and sanitized photo URLs; it is not an exported screenshot, an Open Graph card, or a promise of identical viewport dimensions. It has no interactive descendants and is hidden from assistive technology because the adjacent caption and controls explain its purpose.

## Implementation boundaries

No new dependency, database migration, auth policy, content import, model configuration or tracking service. Existing native buttons, pixel icons and CSS support the entire slice. No idle animation or automatic outbound sharing. Clipboard rejection selects the visible link; native-share cancellation is quiet.

The Vercel project was checked read-only: production tracks `codex/memory-box-mvp`. Feature-branch pushes create a protected preview. **Preview and production currently use the same configured Supabase/AI services**, so intentional contributions in the preview enter the same shared world. This PR does not claim a separate data sandbox.

Context7 was attempted but quota-exhausted; installed Next16client/CSS documentation and current primary web docs were used. Morph exploration/edit returned402, so local searches and `apply_patch` provided the fallback. No paid tool or replacement framework was installed.

## Verification

- Unit coverage includes desktop/phone coordinate preservation, canonical links, signed extremes, invalid inputs, stripped incidental fields and the existing-original boundary regression.
- Actual local app against the configured world: desktop-to-phone arrival, re-sharing, current original/disclosure, build-on, deferred hash navigation, unavailable originals, malformed links, deliberate brush activation,320px overflow, refresh stability, clipboard failure and no content API writes from sharing/arrival.
- Existing live-service regression cases exercise accepted painting reaching another visitor, undo preserving their later pixel, actual provider-backed Ask/source-return, and all three zoom levels on desktop and mobile. Disposable fixtures clean their own exact records.
- Independent source review reproduced the boundary-original crash using a synthetic read-only snapshot; the fix is covered without adding a public boundary fixture. Normal-motion reloads and draft preservation were separately checked.
- Batched desktop/mobile visual review checks the current-content preview, controls, input, narrow widths and source/build-on flow. The new UI passes the Impeccable mechanical detector; reduced-motion uses the existing camera preference and adds no new animated loop.

Final test counts, preview URL and exact branch/production parity are recorded in the PR and the user-facing review package. This is a proposal for product review, not a claim of measured adoption.
