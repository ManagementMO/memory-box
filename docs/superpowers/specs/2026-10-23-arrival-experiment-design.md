# Two arrivals into Memory Box

## Intent and approved scope
Test whether newcomers participate and return more after seeing the occupied world first or arriving inside a readable, lively corner. The user approved both experiences, PostHog, desktop/mobile testing, push and merge. Preserve the white/pastel pixel style, authored positions, real presence, tools and data. No fabricated activity or content.

## Experiences
- `world-first`: frame bounded occupied geography on desktop and mobile, using the existing actual photos, papers, pixels and geographic entrances. No forced flythrough.
- `inside-world`: begin beside a meaningful contributed original and neighboring work at a readable distance, on desktop and mobile. Do not automatically open a reader or obstruct contribution.
- Both use the same content and interface. Shared links win over saved views, which win over experimental arrivals. Missing configuration retains the established arrival. Explicit `?arrival=world-first` / `?arrival=inside-world` previews override a saved camera for review, never overwrite it, and are excluded from analytics and enrollment. A shared link still takes priority over a preview.

## Assignment and measurement
Use PostHog Cloud, one multivariate `arrival-experience-v1` flag, equal `world-first` / `inside-world` allocation, stable anonymous browser identity. Only first-time arrivals without a valid saved view or shared link enroll. Wait at most 1000ms for flags; a timeout keeps the established arrival and records no experiment exposure. Late flags never move the camera. Emit custom `arrival_shown` exposure only after the actual canvas has initialized and become visible. Keep the originally exposed variant on later visit and contribution events even when restoring a saved view. Returning sessions require at least 30 minutes of inactivity; day-based visit events support retention.

Manual events: visit started, arrival shown, original opened, unique place explored, accepted contribution, place shared. Accepted contributions include text/image/link originals, painting and build-on context; clicks, edits, retries, rejected saves, undo and remote activity are not new contributions. Deduplicate by accepted original/operation ID locally without transmitting IDs. Record elapsed time and whether an accepted contribution occurred within five minutes of exposure.

## Boundaries and reliability
No Supabase user ID, name, email, authored text, photo, query, coordinates, URL hash or draft enters analytics. Disable autocapture, replay, surveys, pageview/pageleave and automatic error capture. The SDK evaluates the one arrival flag once, then remote refresh is disabled. All SDK event capture is rejected. Our explicit event/property allowlist sends anonymous events through the official public `/batch/` API with no referrer or credentials. There is no retry queue; opt-out aborts pending event requests. Recheck opt-out/deadline inside and after the browser initialization lock. Production events run only on the canonical hostname; preview, local, automated and QA visits are excluded. Respect DNT/GPC and a visible local opt-out in the existing profile panel. Storage failure, blocked analytics, missing keys and unavailable flags never block the canvas. A concise disclosure describes event-only measurement. No additional motion library or database migration.

## Account setup and release
Use the authorized existing PostHog account if available. Configure project, flag, experiment, custom exposure and contribution/retention insights. Keep secrets out of Git. Launch after both arrivals and instrumentation are deployed and verified. Primary outcome: accepted contribution within five minutes of first exposure. Secondary: stories opened and build-on within five minutes; day-one and day-seven returns via `visit_started`. Require completed conversion/retention windows before comparison. Use custom visit sessions (30-minute inactivity); SDK session counts are not the product metric. Tests are synthetic evidence, not adoption evidence or an experiment winner. Six disclosed installation events have `is_test:true`; custom exposure and dashboard exclude them. Anonymous browser identity cannot follow someone across devices or cleared storage. Event delivery is best effort, so blocked or dropped requests can undercount participation. Record any unresolved account gate explicitly.
